# SG
**SG(Security Group)이란?** AWS VPC 환경에서 EC2, RDS 등 개별 리소스에 직접 연결되는 가상 방화벽이다. 이는 전통적인 ACL과는 달리 상태 저장(Stateful)이라는 특성을 가졌다.같은 서브넷 안에 있어도 인스턴스마다 다른 SG를 붙일 수 있다.

**상태 저장(Stateful)이란?** 나간 트래픽에 대한 응답은 자동으로 허용된다는 것이다. 왜냐면 SG가 연결을 상태로 기억하고 있기 때문이다. TCP 커넥션 단위로 추적해서 요청-응답 페어를 자동으로 매칭시켜준다.

# 규칙 구성 요소
## 인바운드
인바운드/아웃바운드 규칙 하나는 아래와 같이 구성된다.       
항목 | 설명 | 예시 |
---|---|---
Type | 프로토콜 프리셋 | HTTP, HTTPS, SSH, Custom TCP
Protocol | TCP/UDP/ICMP | TCP
Port Range | 포트 | 443, 3306, 8080-8090
Source(인바운드) / Destination(아웃바운드) | 어디서 오는지 / 어디로 가는지 | 0.0.0.0/0, 특정 IP, 다른 SG

## 아웃바운드
아웃바운드는 **리소스가 외부로 나가는 트래픽을 제어한다.** 기본적으로 AWS는 모든 아웃바운드 트래픽을 허용하지만 보안 요구사항이 있는 경우 이 역시 제한할 수 있다.

# 역할
**트래픽 필터링** : 인바운드/아웃바운드 **규칙에 명시되지 않은 트래픽은 기본적으로 전부 거부**된다. 이 덕분에 애플리케이션이 실제로 필요로 하지 않는 포트/프로토콜은 애초에 서버까지 도달하지 못한다.

**리소스 간 통신 경계 설정** : SG를 계층별로 나누고 SG-to-SG 참조로 연결하면 누가 누구에게 접근할 수 있는가라는 통신 경계를 코드/설정 수준에서 명시적으로 강제할 수 있다. 이건 단순히 막아놨다가 아니라 아키텍처의 통신 흐름(ALB → WAS → DB)을 네트워크 레벨에서 강제하는 것이고 나중에 규칙만 봐도 시스템 구조가 파악되는 문서화 효과도 있다.

**최소 권한 원칙 구현** : SG는 기본값이 전체 차단이고 필요한 것만 허용하는 화이트리스트 방식이라 설계 시 강제로 최소 권한을 고민하게 만든다. 이렇게 하면 공격 표면이 좁아지고 특정 인스턴스가 뚫려도 그 인스턴스의 SG가 허용하는 범위 밖으로는 확산이 안 된다.

# 주요 특성
**적용 단위** : EC2, RDS 등 개별 리소스 단위 (서브넷 단위 아님)

**상태 저장** : 인바운드를 허용하면 해당 연결에 대한 아웃바운드는 자동 허용

**허용 기반** : 기본적으로 모든 트래픽은 차단, 허용한 것만 통과 (Deny 규칙 없음)

**다중 할당 가능** : 하나의 리소스에 여러 SG를 중첩 적용 가능하며, 규칙은 OR로 합쳐진다. (더 허용적인 쪽으로 병합, Deny가 없으므로 충돌 개념 자체가 없음)

**SG 참조 가능** : Source/Destination에 IP 대신 다른 SG를 지정 가능하다. 동적으로 IP가 바뀌는 인프라(오토스케일링 등)에도 규칙 수정 없이 대응 가능하다.

# 장단점
## 장점
**응답 트래픽 규칙을 따로 안 만들어도 됨** : 인바운드를 허용하면 그 연결의 응답은 자동으로 나가기 때문에 NACL처럼 **인바운드/아웃바운드를 양쪽 다 신경 쓸 필요가 없고 운영 부담이 줄어든다.**

**SG 참조로 동적 인프라에 유연하게 대응** : Source/Destination에 IP 대신 다른 SG를 지정할 수 있어서 **오토스케일링으로 인스턴스 IP가 계속 바뀌어도 규칙을 수정할 필요가 없다.** IP 하드코딩 방식보다 유지보수 비용이 훨씬 낮다.

**허용 기반 방식이라 최소 권한 원칙을 강제하기 쉬움** : 기본이 전체 차단이고 필요한 것만 열어주는 구조라서 설계 단계에서 **공격 표면을 좁히는 데 유리하다.**

## 단점
**Deny 규칙이 없어서 특정 IP만 콕 집어 차단할 수 없음** : 특정 악성 IP 하나만 막고 싶어도 SG로는 불가능하고 이런 경우에는 NACL을 써야한다. **SG만으로는 세밀한 차단 제어가 안 된다.**

**규칙이 많아지고 여러 SG가 중첩되면 실제 허용 범위 파악이 어려움** : 여러 SG를 붙이면 규칙이 OR로 합쳐지는데 이게 쌓이다보면 **각 인스턴스에 어떤 트래픽이 허용되어 있는지를 한눈에 보기 힘들어진다.**

**인스턴스당 SG 개수와 SG당 규칙 개수에 quota 제한 있음** : 기본값은 낮게 잡혀 있고 대규모 환경에서 세밀하게 SG를 쪼개서 관리하다 보면 이 한도에 걸릴 수 있다. **설계 시 이 제약을 미리 고려해야 한다.**
