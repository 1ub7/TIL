# 종속성
**종속성(Dependency)이란?** 리소스 A를 만들려면 리소스 B가 먼저 있어야 하는 관계이다. 

예를 들어 EC2를 서브넷 안에 띄우려면 서브넷이 먼저 있어야 하고 서브넷을 만들려면 VPC가 먼저 있어야 한다. Terraform은 선언형 도구이기 때문에 Terraform이 리소스들 사이의 종속성을 분석해서 **순서를 스스로 정한다.** 

# 의존성 그래프(DAG)
Terraform은 plan이나 apply 할 때 모든 리소스를 노드로 **종속성을 화살표로 하는 방향성 비순환 그래프(DAG, Directed Acyclic Graph)** 를 만든다. 그리고 아래 세 가지를 결정한다.

- **생성 순서** : 화살표 방향대로 먼저 필요한 것부터 만든다.
- **병렬 처리** : 서로 종속성이 없는 리소스는 동시에 만든다. 기본 동시 작업 수는 10이고 `-parallelism=N` 으로 조절한다.
- **삭제 순서** : `destroy` 할 때는 역순이다. EC2 → Subnet → VPC 순으로 지운다. 서브넷 안에 인스턴스가 남아 있으면 서브넷을 못 지우기 때문이다.

A가 B를 B가 A를 참조하면 고리가 생겨 순서를 정할 수 없으므로 `Error: Cycle`이 발생한다.

# 암시적 종속성(Implicit Dependency)
다른 리소스의 속성을 참조하면 Terraform이 자동으로 종속성을 인식한다. 실무에서 대부분 이 방식이다. 

```hcl
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
}

resource "aws_subnet" "public" {
  vpc_id     = aws_vpc.main.id      # ← VPC를 참조 → 자동으로 VPC가 먼저
  cidr_block = "10.0.1.0/24"
}

resource "aws_instance" "web" {
  ami           = "ami-xxxxxxxx"
  instance_type = "t3.micro"
  subnet_id     = aws_subnet.public.id   # ← 서브넷 참조 → 서브넷이 먼저
}
```

# 명시적 종속성(Explicit Dependency)
코드상 참조는 없지만 실제로는 순서가 필요할 때 직접 적어준다. 대표적인 예시는 IAM 권한이다.

```hcl
resource "aws_iam_role" "app" {
  name               = "app-role"
  assume_role_policy = data.aws_iam_policy_document.assume.json
}

resource "aws_iam_role_policy_attachment" "s3_read" {
  role       = aws_iam_role.app.name
  policy_arn = "arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess"
}

resource "aws_iam_instance_profile" "app" {
  role = aws_iam_role.app.name     # role은 참조하지만, policy_attachment는 참조 안 함
}

resource "aws_instance" "app" {
  ami                  = "ami-xxxxxxxx"
  instance_type        = "t3.micro"
  iam_instance_profile = aws_iam_instance_profile.app.name

  # 인스턴스가 부팅하자마자 S3를 읽는다면,
  # 정책이 붙기 전에 부팅해버리면 권한 에러가 난다.
  depends_on = [aws_iam_role_policy_attachment.s3_read]
}

# EC2가 이 role을 맡을 수 있게 허용하는 신뢰 정책
data "aws_iam_policy_document" "assume" {
  statement {
    actions = ["sts:AssumeRole"]
    principals {
      type        = "Service"
      identifiers = ["ec2.amazonaws.com"]
    }
  }
}
```

EC2는 instance profile → role 까지만 참조한다. 하지만 role에 정책이 붙는 것은 별도 리소스여서 Terraform이 순서를 알 길이 없다. 이럴 때 `depends_on` 으로 “정책 붙고 나서 만들어” 라고 알려준다.

그치만 `depends_on` 은 쓸 수 있으면 쓰는 게 아니라 참조로 해결이 안 될 때만 쓰는 것이다. 이유는 아래와 같다.

- 의존하는 쪽의 변경을 더 보수적으로 처리하게 돼서 plan에 `(known after apply)` 가 불필요하게 늘어난다.
- data 블록에 `depends_on` 을 걸면 그 데이터 조회가 apply 단계까지 미뤄진다. 그러면 plan이 매번 변경이 있는 것처럼 나오는 문제가 생긴다.

왜 걸었는지 코드만 봐서는 모르기 때문에 주석을 꼭 남기는 게 좋다.

# 모듈 간 종속성
모듈끼리도 같은 원리이다. 한 모듈의 output을 다른 모듈의 input으로 넘기면 암시적 종속성이 생긴다. 

```hcl
module "network" {
  source = "./modules/network"
}

module "eks" {
  source     = "./modules/eks"
  vpc_id     = module.network.vpc_id          # ← 암시적 종속성
  subnet_ids = module.network.private_subnet_ids
}
```
