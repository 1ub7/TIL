# minikube
**minikube란?** 단일 노드로 구성된 로컬 Kubernetes 클러스터를 실행하는 도구이다. k8s 로컬 학습/개발 도구 중 가장 오래되고 대중적인 도구이다.

(여기서 **클러스터(Cluster)란?** Kubernetes 전체 시스템 하나를 말한다. 여러 대의 서버를 묶어서 하나의 거대한 컴퓨팅 자원처럼 보이게 만든 것 전체를 클러스터라고 부른다.) 

kind/k3d와의 차이점은 **VM과 Container를 지원하는 것**이다.  
minikube는 **Driver**라는 개념으로 이걸 해결한다. **Driver**는 Kubernetes가 돌아갈 격리된 공간을 무엇으로 만들 것인가를 정하는 옵션이다. minikube 자체는 Kubernetes를 설치하는 로직만 갖고 있고 **그 로직을 어떤 격리 환경 위에서 실행할지는 Driver가 결정**한다는 것이다. 

**VM 드라이버를 쓰면?** VirtualBox나 Hyper-V가 진짜 가상머신을 하나 만들고, 그 안에 Linux+Kubernetes를 통째로 설치한다. 호스트 OS와 완전히 분리된 **격리 수준이 높은 환경**이지만 VM이라 **부팅도 느리고** **리소스도 더 먹는다.**

**Docker 드라이버를 쓰면?** Kind처럼 도커 컨테이너 하나를 노드처럼 사용해서 그 안에 Kubernetes를 설치한다. **VM보다 훨씬 가볍고 빠르다.**

## minikube의 주요 특징
**다양한 드라이버 지원 (VM/컨테이너 선택 가능) :** minikube는 쿠버네티스를 설치하는 로직만 갖고 있고 그걸 어떤 격리 환경 위에서 실행할지는 드라이버가 결정한다. VM 드라이버를 쓰면 완전히 격리된 가상머신 위에 클러스터가 뜨고 Docker 드라이버를 쓰면 컨테이너 기반으로 훨씬 가볍고 빠르게 뜬다. **회사 보안 정책이나 로컬 환경에 따라** Docker를 못 쓰면 VirtualBox로, 빠르게 쓰고 싶으면 Docker로 유연하게 선택할 수 있다.

**Addon 생태계 :** 명령어 한 줄로 Ingress Controller, 모니터링(metrics-server), 대시보드 같은 **부가 기능을 켜고 끌 수 있다.** kind나 k3d는 이런 기능을 쓰려면 공식 매니페스트를 직접 설치해야 하지만 minikube는 커뮤니티가 미리 검증해둔 addon을 자동화해서 원클릭으로 설치해준다. 그래서 **내부 동작 원리를 몰라도 일단 켜서 바로 써볼 수 있어 입문자에게 특히 유리하다.**

**내장 웹 대시보드 : 명령어 하나로 로컬 브라우저가 자동으로 열리면서 Kubernetes 공식 웹 UI가 뜬다.** Pod, Deployment, Service 상태나 로그, 리소스 사용량을 클릭 몇 번으로 확인할 수 있다. kind나 k3d는 이런 대시보드가 기본 제공되지 않아 별도 설치와 `kubectl proxy` 설정이 필요한 반면, minikube는 **이 과정을 명령어 하나로 압축해 CLI에 아직 익숙하지 않은 학습 초기 단계에 특히 도움이 된다.**

# k3s
**k3s란?** SUSE가 만든 경량화된 정식 쿠버네티스 배포판이다. **설치 용량과 리소스 사용량을 극단적으로 줄인 버전**이다. 

**왜 만들어졌을까?** IoT, 엣지 디바이스, 라즈베리 파이 같은 **저사양 환경**에서도 쿠버네티스를 돌릴 수 있게 하기 위해 만들어졌다.

## 경량화 방법
**단일 바이너리화 :** apiserver, scheduler, controller-manager, kubelet, kube-proxy 등을 전부 ‘k3s’라는 하나의 프로세스로 통합했다. **프로세스 개수가 줄어드니 메모리 사용량도 자연히 줄어든다.**

**레거시 코드 제거 :** in-tree 클라우드 프로바이더, 대부분의 **온프레미스/엣지 환경에서 잘 안 쓰는 기능들을 제거**했다.

**기본 저장소 경량화 :** etcd 대신 SQLite를 기본값으로 사용한다. 다만 HA 구성이 필요하면 etcd, MySQL, PostgreSQL로 바꿀 수 있다.

**필수 애드온 기본 내장 :** containerd(컨테이너 런타임), Flannel(CNI, 네트워킹), CoreDNS, Traefik(Ingress Controller), local-path-provisioner(스토리지)가 기본 포함되어 있어서 **별도 설치 없이 바로 실사용이 가능하다.**

# k8s
**k8s란?** 컨테이너화된 애플리케이션을 자동으로 배포, 확장, 관리해주는 오픈소스 오케스트레이션 플랫폼이다. 원래 구글 내부에서 쓰던 Borg라는 시스템을 오픈소스화한 것에서 출발했고 현재는 CNCF가 관리한다.

## k8s의 아키텍처
**컴포넌트(Component)란?** 각 노드 안에서 실제로 돌아가는 개별 프로세스들이다. 노드라는 컴퓨터안에 여러 프로그램이 떠 있는 셈이다.

**컨트롤플레인 컴포넌트란?** 클러스터 전체를 관리하고 의사결정을 내리는 부분이다.

| **kube-apiserver** | 모든 요청이 거쳐가는 관문, `kubectl` 명령도 결국 이 API를 호출하는 것 |
| --- | --- |
| **etcd** | 클러스터의 모든 상태(Key-Value)를 저장하는 분산 저장소, 여기가 죽으면 클러스터 전체가 마비됨 |
| **kube-scheduler** | 새로 생성된 Pod를 어떤 노드에 배치할지 결정 (리소스 여유, 어피니티 규칙 등 고려) |
| **kube-controller-manager** | Deployment, ReplicaSet 등의 원하는 상태를 유지하도록 계속 감시/조정하는 컨트롤러들의 집합 |

**워커노드 컴포넌트란?** 실제로 컨테이너(애플리케이션)가 돌아가는 부분이다.

| **kubelet** | 각 노드에서 API서버와 통신함 실제로 컨테이너를 뜨고 상태를 보고하는 에이전트 |
| --- | --- |
| **kube-proxy** | 노드의 네트워크 규칙 관리 |
| **Container Runtime** | 실제 컨테이너를 실행하는 엔진 |

## 핵심 오브젝트
**오브젝트(Object)란?** Kubernetes 클러스터의 상태를 나타내는 단위이다. **YAML으로 상태를 선언**하면 Kubernetes가 그 상태를 만들고 유지해준다.

| **Pod** | 컨테이너를 담는 가장 작은 배포 단위. 컨테이너 1개 이상을 하나로 묶은 껍데기 |
| --- | --- |
| **Deployment** | Pod를 몇 개 띄울지, 어떤 버전으로 띄울지 관리. 업데이트/롤백도 담당 |
| **Service** | 여러 Pod 앞에 고정된 접속 주소를 붙여주는 것. Pod는 계속 죽고 새로 생기는데 그걸 고정 주소로 감춰줌. |
| **Ingress** | 클러스터 바깥에서 들어오는 HTTP 요청을 어떤 Service로 보낼지 정하는 라우팅 규칙(도메인/경로 기반) |
| **ConfigMap/Secret** | 설정값이나 비밀번호 같은 민감정보를 코드에서 분리해서 관리 |
| **Namespace** | 클러스터 안에서 리소스들을 논리적으로 구역 나누는 것 |
